Этот скилл ОБЯЗАТЕЛЕН при любом изменении файлов в `shared/`. Следуй шагам строго по порядку.

## Шаг 1: Анализ импакта (ДО изменения)

Найди все файлы, которые импортируют изменяемый модуль:

```bash
# Замени <filename> на имя файла без расширения (например: costs, game, economy)
grep -rn "@shared/.*<filename>" garage-2007-frontend/src/ garage-2007-backend/src/ --include='*.ts' --include='*.tsx'
```

Покажи пользователю:
> «Файл `shared/<path>` импортируется в **N файлах FE** и **M файлах BE**: [список]»

## Шаг 2: Классификация изменения

Определи тип:

| Тип | Описание | Риск |
|-----|----------|------|
| **Аддитивное** | Новый экспорт, новое optional поле (`?`) | Безопасно — потребители не ломаются |
| **Модификация** | Изменение типа поля, сигнатуры функции | Потенциально ломающее |
| **Удаление** | Убран экспорт, поле, константа | Точно ломающее |

Для **модификации** и **удаления** — покажи каждый файл-потребитель, который нужно обновить. Не продолжай пока пользователь не подтвердит scope.

## Шаг 3: Внесение изменения

1. Измени файл(ы) в `shared/`
2. Обнови все файлы-потребители в FE и BE
3. Если изменена формула — сверь с `docs/Garage_2007_GBD_v1_1.md`:
   - Если формула совпадает с GBD → ок
   - Если отличается → добавь маркер `// DEVIATION FROM GBD: <reason>`

### Защиты (проверь при внесении)

- Формулы живут ТОЛЬКО в `shared/formulas/`, не дублируются в FE или BE
- Типы для API contract — ТОЛЬКО в `shared/types/`, не дублируются
- `userId` нигде не появился в request body если должен быть из auth context
- Если изменён тип в `shared/types/` — проверь что FE request shape и BE Zod-схема по-прежнему совместимы

## Шаг 4: Верификация (ОБЯЗАТЕЛЬНАЯ)

Запусти последовательно. При ошибке — ОСТАНОВИСЬ и почини.

```bash
# 1. FE type check
cd garage-2007-frontend && npx tsc --noEmit

# 2. BE type check
cd garage-2007-backend && npx tsc --noEmit

# 3. FE тесты
cd garage-2007-frontend && npm run test

# 4. BE тесты
cd garage-2007-backend && npm run test
```

НЕ ПРОПУСКАЙ верификацию. Если хотя бы один шаг упал — почини до продолжения.

## Шаг 5: Отчёт

Покажи:
1. Список всех изменённых файлов (shared + FE + BE)
2. Результаты type check и тестов обеих сторон
3. Предупреждения если остались необновлённые потребители

Если обнаружены проблемы совместимости — предложи запустить `/audit` (full scope).
